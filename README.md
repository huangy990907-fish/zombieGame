# 尸潮 · 人类 vs 丧尸

一个运行在浏览器里的 2D 自主对抗小游戏：50 名人类守在封闭房间里，抵御一波波从门和窗户涌入的丧尸。玩家不直接操控单个单位，而是通过调整参数、切换行为模式和游戏速度来观察战局；另外提供一个独立的「训练场」，用于自由生成单位、改数值、测武器 DPS。

- 技术栈：TypeScript + Vite + PixiJS（渲染到 Canvas）
- 版本：`0.4.3`，变更记录见 [CHANGELOG.md](./CHANGELOG.md)
- 入口：主菜单 → 放置抵抗 / 闯关模式（占位）/ 训练场 / 设置

## 玩法概述

### 目标与胜负

人类全部死亡 → 失败；在本波丧尸清空后且已达到总波数 → 胜利。否则进入约 1.8 秒的波间休整，再开始下一波。

默认总波数为 26，但当前唯一的关卡「初次尸潮」覆盖为 8 波。关卡只覆盖部分参数，其余沿用 `src/data/settings/defaults.ts` 的场景默认值，因此同一套逻辑既能跑默认长局，也能跑短关。

### 波次

- 每波规模：`round(base × growth^(n-1))`，默认 `base = 260`、`growth = 1.09`。
- 狂奔丧尸占比：`min(0.55, 0.25 + n × 0.015)`，逐波提高。
- 丧尸血量：每波 `+5%`（`1 + (wave - 1) × 0.05`）。
- 出场位置：约 25% 从上侧、25% 从下侧、50% 从左侧走廊。
- 生成速度：`min(spawnMax, spawnBase + wave × spawnPerWave)` 只/秒，受同屏上限 `maxAlive` 约束。
- 每波开始补 1 名人类（上限 50），避免一波打崩后完全失去观察价值。

### 场景与开口

逻辑画布固定 `1184 × 720`（74 × 45 个 16px 瓦片），房间为 `224,64 → 1136,656`（墙厚 16），左墙有门、上下墙各有一扇窗。地图几何来自 `public/maps/arena.json`，启动时由 `compileTilesToMapDef()` 编译成现有 `MapDef`；`src/data/maps/arena.ts` 只在 JSON 加载失败时兜底。

| 开口 | 血量 | 破损后通过速度 | 说明 |
|---|---|---|---|
| 门（`door-main`） | 450 | 1.0 | 走廊里的丧尸主要走门，门口火力最密集 |
| 上窗（`window-top`） | 100 | 0.45 | 透明，人类可隔玻璃发现并射击 |
| 下窗（`window-bottom`） | 100 | 0.45 | 同上；破窗后钻窗会被窗檐减速 |

丧尸每啃一口对建筑造成 4 点伤害，啃建筑的间隔是咬人间隔的 1.5 倍。开口血量归零即破损，之后丧尸可以穿过。

**窗洞通行按体型通用判定**：开口净宽小于单位身体直径时不可通行。判定口径统一为「可见体宽 = 2 × 碰撞半径」：普通 11、狂奔 9、胖子 22。门净宽 80、窗净宽 16，因此普通与狂奔都能走窗，胖子只能走门。窗宽是按体型反推的（不是为窗宽扭曲体型）；窄开口在流场和移动碰撞里都按实体墙处理，胖子也不会去啃自己钻不过去的窗。

### 人类 AI

- 初始 50 人，兵种配比按 `LOADOUT = [{ mg: 20 }, { flame: 8 }, { shotgun: 8 }, { rocket: 4 }, { tesla: 10 }]` 随机分配（`src/data/weapons/index.ts`，按武器 id 计数）：机枪 20、喷火 8、霰弹 8、火箭 4、电击枪 10。
- 开局分岗（`src/core/game.ts` 的 `assignPosts()`）：
  - 门口 32 人散兵线，离门约 90px；
  - 每扇窗 4 名机枪岗，位于窗后约 40px、间距 12px（窗净宽 16 后维持 4 人编制）；
  - 中央预备队 10 人（窗口省下的 4 人补到这里）；
  - 喷火 / 霰弹优先守门，机枪补门岗，其余（火箭 / 电击枪 / 剩余机枪）依次补窗岗与预备队。
- 默认「防守」模式：有岗的人站桩守点，只打视野内且在射程内的目标，不主动追击；被逼近到 60px 内会全速后撤拉开距离。没有岗位的人自由游荡。
- 切换「进攻」模式后，人类会主动接敌：太近后撤、太远推进、合适距离侧向绕圈。
- 索敌每 0.25–0.4 秒刷新一次；墙体、完好的门窗会挡视线，窗户透明（带 12px 侧向容差）。
- 开火需要目标在武器射程内，且朝向与目标方向夹角小于约 0.3 弧度。

### 丧尸 AI 与感染

- 房间外：采样 BFS 流场，涌向最近的开口；贴上完好的门窗就开始啃。
- 破口后进入房间：直扑最近的人类。
- 局部分离 + 行走摇摆，避免叠成一团；拥挤时整体减速，形成「堆在门口往里挤」的效果。
- 场上**没有任何存活人类**时（正在转化倒计时中的人类仍算活人），丧尸进入「漫游」状态：每只独立随机选向，移动 1.5–3 秒、停顿 0.4–1.2 秒再换向，移速降为正常的 55%；撞墙会转向，不穿墙、不卡死。漫游时完全不碰门窗，也不触发咬合音效。
- 只要有 1 个活人存在，丧尸行为与之前完全一致；人类重新出现后下一帧就恢复索敌进攻。漫游参数在 `src/data/zombies/index.ts` 的 `WANDER_TUNING`，属于行为规则，没有设置滑块。
- 丧尸撕咬按 `damage` 扣人类真实血量：普通 25、狂奔 18、胖子 40。人类血量归零后才进入转化倒计时（默认 2.8 秒）；倒计时期间人类仍算存活、原地不动、仍可射击，归零后原地变成一只普通丧尸，并计入 `world.infected`。按 25 伤 / 0.55s 的普通僵尸计算，100 HP 的普通人约扛 4 口后异变。
- 人类受伤后头顶出现细血条，3 秒不再受伤后淡出；血条始终水平、不随精灵朝向旋转。训练场「无敌」完全免疫掉血与异变。
- 丧尸受击会减速：按实际伤害换算（每点伤害 4%），最低压到 40% 移速，随后 0.6 秒内线性恢复；多次受击不叠加，只保留当前最强的一次并刷新计时。胖子等大体型（身体直径 ≥ 20）减速幅度减半，最低只到 70%；喷火这类持续伤害每秒最多结算一次减速。

三种丧尸（`src/data/zombies/` 注册表，代码用 id `normal` / `runner` / `fat`，界面显示中文名）：

| 类型 | 血量 | 移速 | 碰撞半径 | 体型直径 | 撕咬间隔 | 撕咬伤害 | 外观 |
|---|---|---|---|---|---|---|---|
| 普通 | 90 | 50 | 5.5 | 11 | 0.55s | 25 | 紫色工装 |
| 狂奔 | 45 | 90 | 4.5 | 9 | 0.7s | 18 | 紫色工装、更瘦 |
| 胖子 | 300 | 32 | 11 | 22 | 0.85s | 40 | 暗粉皮肤 + 暗蓝灰工装，只能走门 |

个体属性会按正态分布在 `±25%` 内随机浮动（设置项「属性随机幅度」）。胖子的碰撞半径是普通的两倍，可见体宽 22px 超过 16px 窗宽，按通用规则无法通过窗洞；体型变大只改通行判定与绘制（游戏内盒宽 33px），子弹命中圈（半径 11 + 3 = 14）与咬人 reach（11 + 6 + 2 = 19）仍按碰撞半径推导。

### 武器

| 武器 | 形态 | 射程 | 伤害 | 冷却 | 弹匣 | 换弹 | 备注 |
|---|---|---|---|---|---|---|---|
| 机枪 | 直线子弹 | 275 | 6 | 0.10s | 60 | 1.4s | 射速高，散布 0.05 |
| 喷火 | 锥形持续伤害 | 158 | 1.3 / 0.06s | 0.06s | 8 轮燃料 | 1.35s | 单轮持续 1.1s，锥形半角 0.32 |
| 霰弹 | 5 弹丸 | 190 | 5.5 / 弹丸 | 0.80s | 7 | 1.6s | 散布 0.24 |
| 火箭 | 弹道 + 爆炸 | 480 | 直接 20，爆炸 44 | 1.90s | 4 | 2.4s | 爆炸半径 62，只伤丧尸 |
| 电击枪 | 瞬时命中 + 链式 | 200 | 34 | 0.90s | 10 | 1.8s | 首个目标 96px 内无其他僵尸时 ×2.2（约 75）；否则向最近可见僵尸逐只跳跃，最多 5 只（含首个），每跳 75% |

命中判定使用「上一帧位置 → 当前位置」的线段扫掠，避免高速子弹穿过丧尸。火箭撞到丧尸、墙或出界都会爆炸。

电击枪是独立的 hitscan 判定：射线投影 + 目标半径 + 墙体/完好门窗的视线检查，没有飞行物。链式跳跃同样要求两僵尸之间视线可见（未破的窗会挡住）；链式上限、跳跃半径、衰减与单体加成参数在 `src/data/weapons/tesla.ts` 的 `tesla` 字段里，可直接调。

## 训练场

### 入口与隔离

主菜单点击「🧪 训练场」，或直接访问 `#/training`。

训练场是一个和正常对局完全独立的 `World`：

- 每次进入都会新建空世界、清零统计；返回主菜单时整个会话被丢弃，改动和单位都不会残留。
- 不修改全局设置（只读定义默认值 + 玩家覆盖值），因此不会影响之后开始的对局。
- 训练场里的人类固定为「进攻」模式，没有正式对局的岗位防守逻辑。
- 没有波次状态机、不会自动刷怪、没有胜负判定。

### 生成与删除

1. 在「僵尸单位」或「人类单位」里点一个类型（按钮会高亮）。
2. 点击战场空地即可生成一个真实存活单位；可以连续点击生成多个。
3. 生成的单位照常走 AI、弹道、伤害与感染逻辑。

其他工具：

- 「🖱 选择/编辑」：点战场上的单位选中它。
- 「🗑 删除」：点单位直接删除；选中单位后编辑器里也有「删除该单位」。
- 「🧹 清场」：清空所有单位、弹道、特效与飘字。
- 「↺ 读数清零」：只清统计和时间，不清单位（方便用同一批单位对比另一组武器）。

生成限制：僵尸不能生成在墙体或实体障碍里（点在实心处会被忽略）；人类会被夹到房间可行走范围内。僵尸可以生成在房间外，便于测试其从走廊冲入的行为。

### 属性编辑

选中单位后，右侧编辑器直接写回该单位字段，立即生效：

- 僵尸：血量（同时更新上限并回满）、移动速度、撕咬间隔（越小越频繁地咬人 / 拆门窗）、攻击力（每次撕咬对人类的掉血量）。
- 人类：武器下拉（切换到任意一种武器，并重置弹药、冷却与喷火状态）、血量、移动速度、视野、伤害倍率（0.2–5）、射速倍率（0.2–5，倍率越大冷却越短）、无敌（完全免疫撕咬掉血与异变）。
- 感染转化中的人类如果勾上无敌，转化倒计时会立即清零，不会被转化。

僵尸攻击力只影响咬人掉血，不影响拆门窗（啃建筑伤害由门窗配置里的「啃建筑伤害」决定）。

### 节奏控制

- 「⏸ 暂停 / ▶ 继续」：冻结逻辑，画面照常渲染。
- 「⏭ 单步」：自动暂停并只前进固定一帧（1/60 秒），便于逐帧观察弹道和命中。
- 「0.25x 慢放」：逻辑以四分之一速度推进。
- 「1x 正常」：恢复常速。

训练场快捷键（仅在该路由生效）：

| 按键 | 作用 |
|---|---|
| `空格` | 暂停 / 继续 |
| `.` 或 `N` | 单步一帧 |
| `1` | 恢复正常速度 |
| `0` | 0.25x 慢放 |

### 实时读数

面板每 120ms 刷新一次，包含：

- 顶部：累计运行时间（不含暂停）、存活人类数、存活僵尸数、总击杀。
- 人类挨咬：被咬次数、累计掉血、异变完成数（与武器 DPS 表分开统计）。
- 电击枪链式读数：放电次数、命中僵尸数、单发平均命中数、单体加成触发次数（独立口径，不混进武器 DPS 表）。
- 武器表（按武器聚合）：总伤、平均 DPS、最近 4 秒滚动 DPS、击杀数、平均击杀耗时。
- 僵尸类型表（按类型聚合）：存活数、承受伤害、被击杀数、平均击杀耗时。
- 伤害飘字：命中时在丧尸头顶显示实际生效伤害，同屏最多 160 条。

统计口径：

- 武器表与僵尸「承伤」只统计人类对僵尸造成的伤害；「人类被咬 / 掉血 / 异变」是僵尸对人类的反向读数，两者不混算。
- 总伤按「实际生效伤害」累计（不超过目标剩余血量）。
- 平均 DPS = 累计伤害 / 累计运行时间。
- 最近 4 秒 DPS 用 8 个 0.5 秒的滚动桶计算。
- 平均击杀耗时 = 单位从「训练场生成」到死亡的平均时间。仅统计训练场手动生成的僵尸。

### 视觉区分

训练场会额外绘制青色全场网格、虚线房间边框、四角标记与地面靶心；选中单位画 8 段弧高亮。正常对局不显示这些装饰。

## 技术栈

| 方面 | 选型 |
|---|---|
| 语言 | TypeScript 5.7（`strict` / `noUnusedLocals` / `noUnusedParameters`） |
| 构建 | Vite 6 |
| 渲染 | PixiJS 8.6（WebGL/WebGPU），绘制到 Canvas |
| UI | 原生 DOM + CSS，HUD 与训练场面板均为覆盖层 |
| 音频 | Web Audio API（`AudioBuffer` 预加载 + 全局限频） |
| 路由 | 自写 hash 路由（`#/menu`、`#/levels`、`#/play`、`#/training`） |
| 存档 | localStorage + File System Access API + JSON 导入导出 |
| 测试 | 无自动化测试，改动后以 `npm run build` + 浏览器实跑为准 |

逻辑采用固定步长 1/60 秒 + 累加器：渲染帧率波动不影响模拟；速度倍率通过「一帧多走几步」实现。空间查询使用空间哈希网格，寻路使用 BFS 流场，子弹与飘字使用对象池 / 数量上限控制内存与 GC 压力。

各模块职责边界：

- `data/` 是唯一的数值来源：实体数值写在各自的定义文件里，地图几何写在地图定义里，玩家改动只作为「覆盖值」保存在设置中，读取时合并。调平衡优先改定义文件。
- 新增僵尸 / 武器 / 人类 / 地图只需新增一个定义文件并在对应注册表登记一行，训练场按钮、统计列与 HUD 会自动跟随，不需要改玩法或 UI 代码。
- `core/world.ts` 只存状态与查询，几何从构造时传入的地图读取；行为在 `systems/`。
- `core/game.ts` 只决定「何时生成、何时结束」。
- 训练场通过 `World` 上的可选字段与 `onDamage` / `onKill` 钩子复用现有玩法，不复制平行逻辑；不设置这些字段时，正常对局行为与之前完全一致。

## 快速开始

环境要求：Node.js 18 及以上（Vite 6 的最低要求），npm。

```bash
npm install
npm run dev       # 开发服务器，默认 http://localhost:5173/
npm run build     # tsc --noEmit 类型检查 + vite build，产物输出到 dist/
npm run preview   # 本地预览 dist/ 构建产物
```

**必须通过 HTTP 服务访问，不能双击 `index.html`。**

原因：`index.html` 通过 `<script type="module" src="/src/main.ts">` 加载源码，浏览器在 `file://` 协议下会拒绝模块加载与部分资源请求，路径也会解析错误；构建后的 `dist/` 同样需要 `npm run preview` 或任意静态文件服务器。直接双击打开只会得到空白页或控制台报错。

## 美术资源

### 像素精灵

单位由 `src/art/` 里的 32×32 俯视像素精灵渲染，不是运行时用代码画的圆形。每个精灵是一个 `SpriteDef`（定义在 `src/art/types.ts`）：

| 字段 | 作用 |
|---|---|
| `id` | 稳定标识，渲染层按 id 取图；人类为 `human-<weapon>`，僵尸为 `zombie-<kind>` |
| `palette` | 字模 → 颜色的调色板，例如 `{ g: "#63a04b" }` |
| `frames` | 帧名 → 32 行字符串，每行 32 个字符，`.` 表示透明 |
| `anchor` | 32×32 内钉在单位逻辑坐标上的中心点（人形为 `(16,17)`） |
| `muzzle` | 开火帧的枪口坐标，子弹与火舌从这里出膛；无武器时为 `undefined` |
| `gameDiameter` / `footprintRadius` | 建议绘制直径与碰撞半径，用于预览页还原 1:1 大小 |
| `facing` | 统一为 `"up"`（枪口指向 -y），运行时按朝向旋转 |

人类与五把武器的组合精灵 `human-mg` / `human-flame` / `human-shotgun` / `human-rocket` / `human-tesla` 由 `src/art/composites.ts` 在模块加载时用 `bakeOverlay` 烘焙，产物是普通 `SpriteDef`；渲染层只按 id 取一张贴图，不再实时叠两层。

### 新增一个单位外观

1. 在 `src/art/sprites.ts` 复制一个现有 `SpriteDef`，改 `id` / `name` / 调色板与帧矩阵，并登记进 `SPRITE_LIST`。
2. 如果是新武器的人类外观，在 `src/art/composites.ts` 的 `MUZZLE_BY_WEAPON` 与武器叠加逻辑里补上对应 id，烘焙会自动生成 `human-<weapon>`。
3. 在数据层新增对应实体：僵尸加 `src/data/zombies/` 并登记到注册表，武器加 `src/data/weapons/`。
4. 打开预览页核对 1×、游戏内尺寸与 8× 放大，并确认 anchor / muzzle 标记落在正确位置。

`src/art/` 不 import 游戏其它模块；与引擎之间的换算（id 查表、朝向旋转、缩放、枪口折算）集中在 `src/render/pixel.ts`。

### 新增实体交付清单

新增僵尸 / 武器 / 地图时按下面清单逐项完成，缺项视为未完成（`TODO.md` 顶部记录了同一约定）：

**1. 数据注册**

- 僵尸：新建 `src/data/zombies/<id>.ts`，在 `src/data/zombies/index.ts` 注册；武器：新建 `src/data/weapons/<id>.ts`，在 `src/data/weapons/index.ts` 与 `LOADOUT` 里登记；地图：新建 `src/data/maps/<id>.ts`，在 `src/data/maps/index.ts` 注册。
- 数值只写在定义文件里，不在设置里重复一份；训练场按钮、统计列与 HUD 会跟随注册表自动出现，不需要手改 UI。

**2. 精灵与动画帧**

- 在 `src/art/sprites.ts` 增加 `SpriteDef`：32×32、32 行 × 32 字符、`.` 表示透明，僵尸为 `zombie-<id>`，人类武器为 `human-<weapon>`（在 `src/art/composites.ts` 补枪口与叠加偏移）。
- 至少包含 idle、移动帧与开火帧；需要倒地表现的补 `death-1…N` 帧序列，并在渲染层按时间推进。
- 打开 `sprites.html` 核对 1×、游戏内尺寸与 8× 放大，确认 anchor / muzzle / footprintRadius 标记位置正确、无空帧、无宽度错误。

**3. 音效**

- 把音频文件放进 `public/audio/`，在 `src/audio/events.ts` 三处登记：`SFX`、`SFX_MAP`、`SFX_THROTTLE`。
- 在 `public/audio/CREDITS.md` 记录来源、许可证、作者与处理方式；已备好但没有调用点的事件要注明，避免误以为已生效。

**4. 文档**

- `README.md`：更新目录结构（如新增目录）、操作说明（如新按钮）、音效事件表与精灵/帧数量。
- `CHANGELOG.md`：在 `[Unreleased]` 写条目。新实体写进「新增」并注明 id 与外观/音效；既有行为变化写进「变更」。
- `AGENTS.md`：目录职责、改动映射或强制约定发生变化时同步更新，保证后续 AI 能只读这一份索引就找到入口。

**5. 训练场与验收**

- 新实体在训练场单位库出现，可生成、可选中，统计列有数值。
- `npx tsc --noEmit` 与 `npm run build` 通过；`#/play`、`#/training` 实跑无 console error。

### 预览页 `sprites.html`

根目录的 `sprites.html` 是独立预览页：左 1× 原生、中按 `gameDiameter` 的游戏内尺寸、右 8× 放大；另有「接入自检」区块叠加 anchor（青色十字）、muzzle（粉色圈）与 `footprintRadius`（灰色虚线圈），可切换描边档位、像素网格与动画速度。

它和主游戏一样必须通过 HTTP 访问：

```bash
npm run dev
# 浏览器打开 http://localhost:5173/sprites.html
```

当前构建只以 `index.html` 为入口，`sprites.html` 仅用于开发期预览，不会进入 `dist/`。

### 视觉缩放

`src/render/pixel.ts` 的 `VISUAL_SCALE = 1.5` 是纯视觉倍数，只乘在精灵缩放上：

| 单位 | 碰撞半径 | 体型/逻辑直径 | 放大后绘制直径 |
|---|---|---|---|
| 人类 | 6 | 12 | 18 |
| 普通丧尸 | 5.5 | 11 | 16.5 |
| 狂奔丧尸 | 4.5 | 9 | 13.5 |
| 胖子丧尸 | 11 | 22 | 33 |

32px 精灵四周有透明留白，1.5 倍后人类可见宽度约 12.4px，接近 12px 的碰撞直径，所以看上去变大、判定没有变。僵尸同理：可见体宽约等于 2 × 碰撞半径（普通约 11.3、狂奔约 8.9、胖子约 22.5），通行判定用 2r，绘制盒宽用 2r × 1.5，1.5 只补透明留白，不再叠加到半径上。碰撞半径、速度、伤害、咬合距离、查询边距与寻路格子全部保持原值；枪口世界坐标同样按放大后的直径折算，子弹仍从枪口出膛。

## 音效系统

### 事件与文件

音效事件定义在 `src/audio/events.ts`，共 **18 个**：

| 分组 | 事件 |
|---|---|
| 武器 | 机枪射击、喷火、霰弹、火箭发射、火箭爆炸、电击枪放电、换弹 |
| 丧尸 | 追击咆哮、胖子低吼、啃咬、被命中、击杀 |
| 人类 | 受伤、转化倒戈 |
| 场景 | 波次开始、胜利、失败 |
| UI | 点击 |

`SFX` 的每个值同时是文件名主干，`SFX_MAP` 映射到 `audio/<事件名>.mp3`。文件放在 `public/audio/`，Vite 会原样拷贝到 `dist/audio/`，运行时以相对路径 `audio/...` 请求。

新增一个音效需要四步：

1. 在 `src/audio/events.ts` 的 `SFX` 里加事件；
2. 在 `SFX_MAP` 里登记 `audio/xxx.mp3`；
3. 在 `SFX_THROTTLE` 里设置全局限频（毫秒，`0` 表示不限频）；
4. 把同名 mp3 放进 `public/audio/`。

### 播放行为

`src/audio/manager.ts` 导出单例 `sound`：

- 启动时创建 `AudioContext`，用 `decodeAudioData` 预加载全部 18 个文件为 `AudioBuffer`。
- 播放时 `createBufferSource` 一次性输出，延迟低、并发稳定。
- 同一音效受 `SFX_THROTTLE` 全局限频（例如机枪 40ms、咆哮 3000ms），避免几十人同时开火导致音频爆炸。
- 文件缺失或解码失败时静默降级：该事件不发声，不抛错，只在控制台 `debug` 记录。
- 受浏览器自动播放策略限制，首次用户交互前不会出声；进入主菜单或选关页时会暂停音频，进入战斗或训练场再恢复。
- 支持总音量、音效音量、静音切换；音量滑块即时生效，其余参数在「重开」后生效。

### 授权台账

`public/audio/CREDITS.md` 逐文件记录来源、许可证与处理方式：

- 18 个 mp3 均为 **freesound.org 的 CC0 1.0 素材或其派生**（不含程序化合成文件），可复制、修改、商用，无需署名或授权费。`zombie-growl-fat.mp3` 由 `zombie-growl.mp3` 降调/降速生成，`weapon-tesla.mp3` 又由 `zombie-growl-fat.mp3` 升调/高通/颤音派生，授权均随原文件。
- 每个文件的 freesound id、原始标题、作者、许可证链接与处理说明都在台账表格中逐条列出；具体来源以 `CREDITS.md` 为准。
- 统一后处理规格：44.1kHz / 单声道 / MP3 128kbps / 峰值约 -3dB / 去静音头 / 按用途裁剪并加淡入淡出。
- 其中 `weapon-reload`、`human-hurt` 两个事件已声明、文件已备好，但游戏代码目前没有调用点，因此不会发声。

素材已随 0.2.0 入库（提交 `949e1db`，tag `v0.2.0`）；目录内容与台账一一对应，可直接核对。

## 参数与存档

顶栏「⚙ 设置」打开参数控制台，共 21 个滑块，分 5 组：

| 分组 | 内容 |
|---|---|
| 波次 / 规模 | 总波数、首波尸数、波次增长、每秒最大生速、同屏僵尸上限 |
| 人类配置 | 初始人数、人类血量、移速、视野、转化倒计时 |
| 僵尸配置 | 属性随机幅度、普通/狂奔的血量与移速均值 |
| 门窗配置 | 门血量、窗血量、破窗后穿窗速度、啃建筑伤害与减速 |
| 音频 | 总音量、音效音量 |

修改滑块后点「重开」生效（音量即时生效）。「恢复默认」会清空所有覆盖值，回到各定义文件里的默认数值。

滑块只记录「你改过什么」：设置里保存的是覆盖值，读取时按「覆盖值 ?? 实体/地图定义默认值」合并。`runtime.ts` 会按 id 读取任意僵尸的血量/移速覆盖值，但设置面板的滑块列表写在 `src/data/settings/sliders.ts`（静态），当前只登记了普通/狂奔；胖子暂时只能在训练场按单位调，或直接改 `fat.ts` 默认值。

存档分三层兜底：

1. 每次修改自动写 localStorage；
2. 在支持的浏览器（Chrome / Edge + localhost 或 HTTPS）可选择本地目录，额外自动写 `settings.json`；
3. 支持导出 / 导入 JSON，便于跨设备搬运。

`0.3.0` 起设置存档格式变更（localStorage 键 `zombieGame.settings.v2`，`SAVE_VERSION = 2`）。旧版本存档不再兼容：读到旧格式时直接回落默认值，不抛异常、不阻塞启动；需要保留旧参数的话，请在升级前用「导出 JSON」备份。

关卡进度（已解锁、已通关）同样保存在 localStorage，目前只有 `level-1` 一个关卡。主菜单「放置抵抗」直接进入第一关，进度在选关/结算流程中自动读取。

主菜单「设置 → 清空存档」会删除 `zombieGame.progress.v1` 与所有 `zombieGame.challenge.*` 预留 key（闯关模式尚未实现，暂无实际数据），但**不会**删除 `zombieGame.settings.v2`、`settings.json` 或音量偏好。清空后内存中的进度同步重置，下一次开局从第一关开始。

## 已知限制

**玩法与数值**

- 人类血量现在是真实生命值，但正常对局的人类 AI 仍以走位和火力为主；血量归零后不会立即死亡，而是进入原有 2.8 秒转化流程。训练场可以调人类血量与僵尸攻击力来观察这个过程。
- 训练场「无敌」完全免疫撕咬掉血与异变；「人类血量」滑杆会真实改变该单位的初始/当前血量。
- 僵尸攻击力只有训练场按单位调整，尚未进入对局内全局滑块表；普通/狂奔/胖子的默认攻击力写在各自的 `src/data/zombies/*.ts`。
- 感染转化出来的新僵尸没有记录出生时间，因此**不计入平均击杀耗时**；它的击杀数仍会归入对应僵尸类型的击杀统计。
- 「清场」只清单位、弹道、特效与飘字，**不清读数**；要继续干净统计需点「读数清零」。
- 训练场没有波次、自动刷怪和胜负，人类固定为进攻模式，无法复现正式对局的岗位防守与分岗。
- 「零人类时丧尸漫游」在正常对局里较难观察：波次中人类全部死亡会立即判负并停止推进。想验证漫游，请在训练场清场后生成僵尸，再单独生成 1 个人类观察恢复进攻。
- 胖子（`fat`）身体直径 22 > 窗洞净宽 16，按通用通行规则只能走门；破损的窗对它仍是实体墙，它也不会去啃自己钻不过去的窗。普通（11）与狂奔（9）仍可从破窗进入。
- 窗净宽改为 16px 后，窗岗维持每扇 4 人（间距 12px）。窄窗降低了窗外尸群的涌入速度，但窗口火力线也同步减少；若后续觉得窗口太容易漏，优先回调窗岗人数而不是重新放宽窗宽。
- 胖子的血量/移速暂时没有对局内设置滑块（滑块表静态登记了普通/狂奔），需要调它请用训练场单单位编辑或改 `src/data/zombies/fat.ts`。
- 「闯关模式」只有主菜单入口与「尚未实现」占位弹窗，不会进入任何页面；清空存档会一并清理为其预留的 `zombieGame.challenge.*` key。

**工程与内容**

- 目前只有 1 个关卡（`level-1`「初次尸潮」，8 波）和 1 张地图（`arena`）。地图已改为 `public/maps/*.json` + manifest 的运行时加载结构（0.5.0 阶段 0），但入口仍只用默认地图，还没有地图选择或工坊编辑器。
- 0.5.0 阶段 0 的地图格式限制：画布固定 `74 × 45` 格（`16px`），不支持自定义尺寸；校验暂时只接受 **1 门 + 2 窗**（守岗仍按「0 = 门、1/2 = 窗」固定口径），任意户型与通用守岗留到后续阶段；`arena` 是只读内置地图，工坊只能另存副本。
- 地图 JSON 加载失败、manifest 非法或校验不通过时，会回退 `src/data/maps/arena.ts` 的 0.4.3 TS 兜底几何（画布 `1180 × 720`、窗宽 18），并在 console 输出 `[maps]` warning；正常路径下以 `public/maps/arena.json` 编译出的 `1184 × 720` / 窗宽 16 为准。
- 音效：18 个事件已接线，素材均为 freesound CC0 录音或其派生；但 `weapon-reload` 与 `human-hurt` 没有调用点，放入文件也不会响。
- 美术：单位与武器已改为 32px 像素精灵（`src/art/`，17 精灵 / 51 帧，含 5 个 `human-<weapon>` 组合），但只为「朝上」方向烘焙了一帧集，运行时按朝向线性旋转，任意角会有轻微锯齿；特效与场景装饰仍由 Pixi 代码绘制。
- 电击枪是瞬时命中，链式最多 5 只且每跳都要求视线可见；未破的门窗会挡住后续跳跃，想观察满 5 跳请在训练场把僵尸排成一条并在同侧放置，或先把窗打破。链式半径/上限/衰减/单体加成都在 `src/data/weapons/tesla.ts` 的 `tesla` 字段，没有全局滑块。
- 没有自动化测试；`npm run build` 只做类型检查与打包，行为正确性依赖浏览器实跑。
- 面向桌面浏览器：训练场需要鼠标精确点选，未做移动端触控适配。
- 顶栏速度按钮支持 8x，但键盘只覆盖 1x / 2x / 4x。
- 训练场的单位、改动和统计不落盘，退出路由即重置。

## 版本与 CHANGELOG 约定

- 版本号遵循 [Semantic Versioning](https://semver.org/lang/zh-CN/)：`MAJOR.MINOR.PATCH`。当前处于 `0.x`，破坏性重构也可能出现在 `MINOR` 里，但会在 CHANGELOG 明确标注。
- `package.json` 的 `version` 是版本的唯一来源。发版时同步更新 `package.json`、`CHANGELOG.md`，并打 **annotated tag** `vX.Y.Z`：

```bash
git tag -a v0.4.3 -m "0.4.3: 人类血量与僵尸攻击力、受击减速、电击枪、截图精简"
git push origin main
git push origin v0.4.3
```

- `CHANGELOG.md` 采用 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/) 风格，中文条目，新版本在上、旧版本在下；日期统一写 `YYYY-MM-DD`。
- 每个版本按需分组：`新增` / `变更` / `修复` / `移除` / `安全`；同一版本内按重要性排列。
- 尚未发布的内容写进 `Unreleased` 段。**只有实际完成并验证的内容才能从 `Unreleased` 移到版本段**，进行中的工作保持在 `Unreleased` 并注明「进行中」。
- 提交信息建议使用约定前缀：`feat:`、`fix:`、`docs:`、`perf:`、`refactor:`、`chore:`。本文件的维护提交使用 `docs:`。
