# 尸潮 · 人类 vs 丧尸

一个运行在浏览器里的 2D 自主对抗小游戏：玩家在关卡的人类区内放置不同武器的人类，管理各自的库存与恢复，抵御一波波从门和窗户涌入的丧尸。玩家不直接操控单个单位，而是通过放置、切行为模式和游戏速度来观察战局；另有独立的「训练场」，用于自由生成单位、改数值、测武器 DPS；「尸潮求生」是单角色 Roguelike 生存模式，玩家亲自移动、自动开火、升级变强，只计失败。开发者还可以在选关页新建 / 编辑关卡。

- 技术栈：TypeScript + Vite + PixiJS（渲染到 Canvas）
- 版本：`0.8.2`，变更记录见 [CHANGELOG.md](./CHANGELOG.md)
- 入口：主菜单 → 放置抵抗（选关）/ 尸潮求生 / 训练场 / 设置；开启开发者模式后主菜单额外出现「地图工坊」，选关页额外出现关卡编辑入口

## 玩法概述

### 目标与胜负

进入关卡后先进入**准备阶段**：地图上显示半透明的人类区（绿色）与僵尸区（红色），页面右侧固定着库存面板（窄屏改为底部横排）；玩家在人类区内点击放置人类，点「开始」后才隐藏区域标记并放第一波，开始按钮随即从界面移除。

- **胜利**：关卡配置的所有波次都生成完，且场上僵尸清零。
- **失败**：已经放置过人类、场上又不存在任何人类（正在转化倒计时的人仍算存在，转完才算消失）。
- 还没放置过任何人类时不判负，只提示「至少放置一名人类」，避免开局误判。

关卡参数全部来自 `public/levels/<id>.json`：绑定地图、人类种类（= 武器种类）的血量与库存、每波僵尸种类与只数、波间间隔。内置教学关「初次尸潮」为 8 波共 1186 只。

### 波次

- 波数与每波内容：由关卡 JSON 的 `waves` 决定，一波内可以同时配置多种僵尸与各自只数。
- 波间间隔：取该波 `interval`（缺省 1.8 秒），全部波次生成完且场上无僵尸即胜利。
- 丧尸血量：每波 `+5%`（`1 + (wave - 1) × 0.05`）。
- 出场位置：只从地图显式提供的多块 `spawn` 与可选 `windowSpawn.top/bottom` 区域按面积加权抽签。
- 生成速度：`min(spawnMax, spawnBase + wave × spawnPerWave)` 只/秒，受同屏上限 `maxAlive` 约束；这些仍可由关卡 `settings` 覆盖。
- 正式对局**不再自动补人**：人类只能靠库存恢复后由玩家继续放置。

### 场景与开口

逻辑画布固定 `1184 × 720`（74 × 45 个 16px 瓦片）。默认地图 `arena` 的房间为 `224,64 → 1136,656`（墙厚 16），左墙有门、上下墙各有一扇窗；内置 `test-yard` 的房间更窄且向右偏移，`test-multi` 是 2 门 3 窗的任意户型回归图。地图几何来自 `public/maps/*.json`，启动时由 `compileTilesToMapDef()` 编译成现有 `MapDef`；`src/data/maps/arena.ts` 只在 JSON 加载失败时兜底。瓦片字符为 `.` 空地 / `#` 墙 / `w` 窗 / `d` 门 / `g` 草丛 / `~` 水池。区域字段 `humanZone` / `spawn` 支持单个矩形或矩形数组（保存统一写数组，旧对象形态仍可读取）。

训练场右侧面板顶部新增「地图」下拉，可在内置图（`arena` / `test-yard` / `test-multi`）与工坊图之间切换，选项优先显示地图名称、id 作为次要信息；`#/play` 仍按关卡绑定的地图运行，当前没有面向对局的选图界面，调试时可用 `?map=<id>` 指定地图（例如 `?map=test-yard#/play`、`?map=test-yard#/training`）；id 不存在会回退默认图并在页面顶部提示。

| 开口 | 血量 | 破损后通过速度 | 说明 |
|---|---|---|---|
| 门（`door-main`） | 450 | 1.0 | 走廊里的丧尸主要走门，门口火力最密集 |
| 上窗（`window-top`） | 100 | 0.45 | 透明，人类可隔玻璃发现并射击 |
| 下窗（`window-bottom`） | 100 | 0.45 | 同上；破窗后钻窗会被窗檐减速 |

上表为默认地图 `arena` 的数值。每扇门窗的血量 / 通行速度都取自自己的 JSON 字段（例如内置 `test-multi` 的两扇门 300/500 血，三扇窗 60/90/120 血且速度各不相同）；玩家设置里的门 / 窗覆盖仍按种类统一生效，优先级高于逐扇默认值。

丧尸每啃一口对建筑造成 4 点伤害，啃建筑的间隔是咬人间隔的 1.5 倍。开口血量归零即破损，之后丧尸可以穿过。

**窗洞通行按体型通用判定**：开口净宽小于单位身体直径时不可通行。判定口径统一为「可见体宽 = 2 × 碰撞半径」：普通 11、狂奔 9、胖子 22、飞扑者 8、腐蚀者 11、人类 12。门净宽 80、窗净宽 16，因此普通与狂奔都能走窗，胖子只能走门，人类只能走破窗。窗宽是按体型反推的（不是为窗宽扭曲体型）；窄开口在流场和移动碰撞里都按实体墙处理，胖子也不会去啃自己钻不过去的窗。

**人类与丧尸共用同一套阻挡判定**：墙体、地图边界、完好的门窗一律不可穿；已破坏的开口只有净宽 ≥ 自身身体直径时才可通行。人类移动（含巡逻目标、被分离力推挤）、随机出生落点与训练场点选生成都走 `src/systems/collision.ts` 的 `isBlockedForBody`，不再只靠 `humanBounds` 夹取。阻挡矩形按**碰撞半径**（`bodyDiameter / 2`）向外扩张，单位停在身体外缘贴墙，不再以中心点贴墙插进墙体；扩张只作用于实体阻挡，不改变开口通行口径（净宽仍按身体直径判定），所以普通丧尸照样能过 16px 破窗、胖子照样被挡。丧尸的地图边界夹取同样按碰撞半径，身体不越出画布。

### 地形（0.8.0）

地图支持两种地形瓦片，数值集中在 [terrain.ts](./src/data/terrain.ts)：

| 地形 | 瓦片字符 | 阻挡单位 | 子弹 / 射线 | 效果 |
|---|---|---|---|---|
| 草丛 | `g` | 否（可通行） | 穿过 | 人类与丧尸移速 ×0.8；人类索敌半径 ×0.5（丧尸索敌不变）；被喷火覆盖后燃烧 1.5 秒，期间效果完全失效、渲染变浅 |
| 水池 | `~` | 是（人类 / 丧尸与寻路） | 穿过（不挡视线） | 作为连通区域图的不可穿越边界，不进入开口候选 |

- 草丛燃烧结束后等待 10 秒，再用 1 秒渐隐重生，恢复原色与原效果；重生期间效果按渐隐进度线性恢复。
- 水池刻意不写入 `map.walls`：子弹与电击枪射线只检查 `map.walls` 的阻挡，所以仍可穿过水面射击；单位碰撞与寻路则通过 `waterBlockers` 并入世界阻挡。
- 工坊编辑器画笔栏新增「草丛」「水池」与地形擦除，支持绘制、拖拽、撤销重做，草稿 / 导入导出 / 试玩全链路可用；训练场面板也提供同样三种地形工具，便于即时观察减速、索敌、燃烧重生与子弹穿透。
- 旧地图 JSON 没有地形字段时按空数组处理，现有 `arena` / `test-yard` / `test-multi` / `open-field` / 工坊图行为不变。

### 放置与库存

- 人类种类与武器种类一一对应：`mg`（机枪）/ `flame`（喷火）/ `shotgun`（霰弹）/ `rocket`（火箭）/ `tesla`（电击枪）/ `sniper`（狙击枪），没有单独的「手枪」种类。
- 每种人类的血量、初始库存、库存上限、恢复间隔都在关卡 JSON 的 `humans` 里独立配置；同一武器在本关内共享一档血量。
- 库存面板固定在页面右侧一栏（宽 252px），游戏画布按剩余宽度等比缩放、不被遮挡；窗口宽度 ≤ 900px 时右栏改为底部横排，避免挤压画布。
- 库存面板每 0.1 秒刷新：满仓停表，未满时按各自 `regen` 秒 / 个独立恢复；数字键 `1–6` 切换当前选中的人类（对应卡片右上角编号）。点「开始」后「开始」按钮直接从 DOM 移除，只保留波次与库存信息。
- 在人类区内点击空地即可放置：扣 1 库存，落点即守岗点并朝向最近开口；点在墙内、门窗实体或不可通行处不生成、不扣库存。
- 放下的单位立即接入现有守岗 AI（见下节），行为模式仍可在顶栏「防守 / 进攻」间切换。

### 人类 AI

- 正式对局不再开局生成 50 人、也不再自动分岗；所有人类都由玩家放置，`settings.human.start` 在放置模式下不参与生成。
- 默认「防守」模式：站桩守点，只打视野内且在射程内的目标，不主动追击；被逼近到 60px 内会全速后撤拉开距离。
- 切换「进攻」模式后，人类会主动接敌：太近后撤、太远推进、合适距离侧向绕圈。
- 索敌每 0.25–0.4 秒刷新一次；墙体、完好的门窗会挡视线，窗户透明（带 12px 侧向容差）。
- 开火需要目标在武器射程内，且朝向与目标方向夹角小于约 0.3 弧度。

### 丧尸 AI 与感染

- 默认追击模式 `breach`（按僵尸类型在 `src/data/zombies/<id>.ts` 的 `pursuit` 字段配置，缺省按 `breach`）：以「连通区域 + 可破坏开口」决策。完好的门窗视为不可穿越边界，已破开口只有净宽 ≥ 自身身体直径才算通道。
- 本连通区域内有活人：沿「以活人为源」的 BFS 流场绕墙直追最近活人，不主动破门窗。
- 本区没有活人：在区域邻接图上跑最短路（边权 = 走到开口的距离 + 按开口血量与啃咬节奏估算的破拆耗时），在所有有活人的可达区域里选总代价最小的目标，取路径上的第一扇可破坏且自己钻得过的开口去啃；破掉后立即重算连通关系，其它僵尸下一帧同步按新区域更新，不等全局刷新。
- 体型过滤：胖子（身体直径 22）只把净宽够的门当候选，16px 窗即使破开也过不去，因此不会去撞窗；区域边界只有不可破坏墙、或只剩自己过不去的窗时退化为漫游（慢晃 / 偶尔停顿），不贴墙顶门。
- 多层阻断可逐层推进：A 区破门进 B 区、再破窗进 C 区。破口后进入新区域，直扑最近的人类。
- 已有 `direct` 模式保留旧行为（无视分区直接朝全场最近人类走）；新类型可在定义里选或扩 `ZombiePursuitMode` 并在 `systems/ai.ts` 分发。
- 局部分离 + 行走摇摆，避免叠成一团；拥挤时整体减速，形成「堆在门口往里挤」的效果。
- 场上**没有任何存活人类**时（正在转化倒计时中的人类仍算活人），丧尸进入「漫游」状态：每只独立随机选向，移动 1.5–3 秒、停顿 0.4–1.2 秒再换向，移速降为正常的 55%；撞墙会转向，不穿墙、不卡死。漫游时完全不碰门窗，也不触发咬合音效。
- 只要有 1 个活人存在，丧尸行为与之前完全一致；人类重新出现后下一帧就恢复索敌进攻。漫游参数在 `src/data/zombies/index.ts` 的 `WANDER_TUNING`，属于行为规则，没有设置滑块。
- 丧尸撕咬按 `damage` 扣人类真实血量：普通 25、狂奔 18、胖子 40、腐蚀者 15；飞扑者不撕咬人类，伤害来自扑倒后的压制（每秒 8 点，求生模式为 4 点）；母体与尖叫者同样不能主动攻击人类。人类血量归零后才进入转化倒计时（默认 2.8 秒）；倒计时期间人类仍算存活、原地不动、仍可射击，归零后原地变成一只普通丧尸，并计入 `world.infected`。按 25 伤 / 0.55s 的普通僵尸计算，100 HP 的普通人约扛 4 口后异变。
- 人类受伤后头顶出现细血条，3 秒不再受伤后淡出；血条始终水平、不随精灵朝向旋转。训练场「无敌」完全免疫掉血与异变。
- 丧尸受击会减速：按实际伤害换算（每点伤害 4%），最低压到 40% 移速，随后 0.6 秒内线性恢复；多次受击不叠加，只保留当前最强的一次并刷新计时。胖子等大体型（身体直径 ≥ 20）减速幅度减半，最低只到 70%；喷火这类持续伤害每秒最多结算一次减速。

七种丧尸（`src/data/zombies/` 注册表，代码用 id `normal` / `runner` / `fat` / `leaper` / `corroder` / `screamer` / `matriarch`，界面显示中文名）：

| 类型 | 血量 | 移速 | 碰撞半径 | 体型直径 | 撕咬间隔 | 撕咬伤害 | 外观 |
|---|---|---|---|---|---|---|---|
| 普通 | 90 | 50 | 5.5 | 11 | 0.55s | 25 | 紫色工装 |
| 狂奔 | 45 | 90 | 4.5 | 9 | 0.7s | 18 | 紫色工装、更瘦 |
| 胖子 | 300 | 32 | 11 | 22 | 0.85s | 40 | 暗粉皮肤 + 暗蓝灰工装，只能走门 |
| 飞扑者 | 28 | 150 | 4 | 8 | 0.6s | —（压制 8/秒） | 四脚爬行、体型最小，明显快过狂奔 |
| 腐蚀者 | 55 | 38 | 5.5 | 11 | 0.65s | 15 | 接近普通体型，移速更慢，远程吐毒 |
| 尖叫者 | 40 | 60 | 5.5 | 11 | 0.8s | —（只啃门窗） | 瘦弱长发、修长指甲，周期性尖叫强化周围僵尸 |
| 母体（BOSS） | 4000 | 22 | 20 | 40 | 1.2s | —（只啃门窗） | 肉山体型，64×64 精灵网格，只能走门 |

个体属性会按正态分布在 `±25%` 内随机浮动（设置项「属性随机幅度」）。胖子的碰撞半径是普通的两倍，可见体宽 22px 超过 16px 窗宽，按通用规则无法通过窗洞；体型变大只改通行判定与绘制（游戏内盒宽 33px），子弹命中圈（半径 11 + 3 = 14）与咬人 reach（11 + 6 + 2 = 19）仍按碰撞半径推导。

#### 飞扑者（0.8.2）

- 最近**可见**人类进入 120px 后原地蓄力 0.8 秒；蓄力期间受击不打断，每次受击延长 0.12 秒，剩余时长上限 2.0 秒。
- 蓄力完成以 3 倍移速直线扑向目标；扑空（撞墙或飞行时间耗尽）进入 1 秒硬直。
- 扑中后目标进入**压制**：3 秒内不能开火、移速 ×0.4、每秒掉 8 点血；飞扑者压在原地不动。求生模式有独立平衡：压制 1.5 秒、每秒 4 点（走 `SURVIVAL_ZOMBIE_OVERRIDES`，不改这里的基数值）。同一人类同时只能被 1 只压制，压制者被击杀或时间到自动挣脱。人类仍是血量归零才异变。
- 被压制的人类有可读提示：紫红染色 + 脚下脉动紫环与四道粉色爪痕（渲染层绘制，不新增美术素材）。

#### 腐蚀者与腐蚀毒液（0.8.2）

- 对 200px 内可见人类远程吐毒，冷却 3.5 秒；毒液落在人类当前位置，半径 40px、持续 6 秒、每秒 6 点伤害、池内人类移速 ×0.8。求生模式中毒液为每秒 4 点（其余字段沿用基础定义）。
- 毒液是世界状态 `World.poison`，与草丛一样由 `tickTerrain` 统一推进；只伤害人类，不伤害丧尸，不阻挡单位、子弹与电击射线，也不挡视线（可正常通行）。
- 多团毒液重叠时“同位置取最高”：伤害取最大值、减速取最强值，不叠加；同位置（中心相距 ≤ 8px）更强的毒液会替换 / 刷新较弱的一团。
- 腐蚀者死亡时在尸体位置额外留下一团毒液：半径 48px、持续 5 秒，伤害与减速沿用吐出的毒液（同源数据）。
- 训练场不新增毒液 / 飞扑参数滑块，基础模式专属数值在 `src/data/zombies/leaper.ts` 与 `corroder.ts`，求生模式差异值在 `src/data/survival/config.ts` 的 `SURVIVAL_ZOMBIE_OVERRIDES`，需要时可在训练场逐单位调血量 / 移速 / 咬人间隔。

#### 母体（BOSS，0.8.2）

- 半径 20（身体直径 40），能通过 80px 门、无法通过 16px 窗；血量 4000、移速 22，`pursuit: "breach"`。不能主动攻击人类（不撕咬、不产生撕咬伤害），但仍会啃门窗。
- 每 6 秒产 **2 只**求生池中的非 BOSS 僵尸；由它产出的子体同屏最多 **10 只**（只统计仍然存活的子体）。达到上限后暂停产卵，等子体被清掉再补。
- 子体围绕母体环形采样空地，必须在地图内、不落在墙体 / 水池里，并与母体身体保持间距；某一轮找不到空位就少产一只，等下一轮。
- 被击杀时原地一次性产出 **12 只**非 BOSS 僵尸作为最后一波（不受同屏上限约束）。
- 母体子体击杀经验按正常值的 **70%** 折算（`Zombie.xpMul = 0.7`）。
- 场上只要存在母体，画面顶部显示一条全局 BOSS 血条（所有模式通用）；多只母体时取当前血量最高的一只显示，并标出总数。求生模式中它同时充当 BOSS 进度条。

#### 尖叫者（0.8.2）

- 血量 40、移速 60、半径 5.5、`pursuit: "breach"`；不能主动攻击人类，只能啃门窗。
- 每 8 秒尖叫一次，强化半径 **200px** 内的其他僵尸，持续 **6 秒**：移速 +30%、攻击力 +50%、受伤减免 30%。
- 不强化母体等 BOSS，也不强化自己；多次尖叫只刷新持续时间并取更强倍率。被强化的僵尸有粉紫染色与脚下脉动粉环提示（渲染层绘制，不新增素材）。
- 求生模式从玩家 3 级起进入普通出怪权重表，数值按实测定，见 `SURVIVAL_ZOMBIE_WEIGHTS`。

## 尸潮求生（0.7.0）

单角色 Roguelike 生存：没有胜利，只有失败，重开完全重置。

- **入口**：主菜单「🧟 尸潮求生」或地址栏 `#/survival`。进入后先在卡片里选地图：默认「空旷地」，也可选其它内置图或工坊图。玩家模式可玩所有已有地图；开发者模式额外显示「打开地图工坊」，与放置模式一致（玩家看不到编辑入口）。
- **地图**：默认内置只读地图「空旷地」（`open-field`）是一整片空地，无墙、无门窗；地图校验允许完全空白的画布存在 0 扇开口。
- **出生点**：地图中心；若地图定义了人类区，则取人类区并集的面积质心。
- **忽略区域语义**：人类区 / 僵尸区不限制本模式玩法，出怪只按距离与可通行规则选点。
- **玩家**：单名人类，初始武器冲锋枪 `mg`，血量与移速沿用人类定义（100 HP / 54 速度）。`WASD` 或方向键移动，逐轴碰撞、贴墙滑动；地图边界按身体半径夹取。镜头跟随玩家并按地图边界夹取。
- **双武器**：最多同时持有 2 把，初始只有 `mg`；通过升级「获得新武器」从 `SURVIVAL_WEAPON_POOL` 里尚未持有的武器中二选一。两把武器各自独立维护弹药、冷却、换弹与喷火计时，同一帧可各自开火；角色精灵显示主武器，HUD 用武器芯片列出副武器。
- **战斗**：自动索敌（复用最近可见目标逻辑）、自动开火，朝向跟随目标。被丧尸撕咬掉血（承伤倍率 0.45），血量归零立即失败。
- **经验与升级**：丧尸死亡 85% 掉落经验球，玩家靠近 48px 内自动吸附（拾取范围可升级）。经验满后游戏暂停并弹出三选一，池中包括：
  - 火力强化（伤害 +15%）、急速装填（射击间隔 ×0.92）、强健体魄（血量上限 +20 并回复 20）、轻装疾行（移速 +8%）、武器升级（主武器 1→3 级，逐级提升伤害并缩短射击间隔）；
  - 获得新武器（二段选择，最多同时持有 2 把）；
  - 额外投射物 +1（最多 4 层：机枪 / 火箭多一发弹道、霰弹多一颗、电击枪多一道独立选目标的电弧，电击枪链式仍受 5 跳上限）；
  - 致命一击（暴击率 +8%）、暴击强化（暴击伤害 +30%）、嗜血（每次击杀回复 2% 最大生命）、磁力扩散（经验拾取范围 +25%）。
  - 奖励可重复获得、永久累乘；武器满级后不再进入池，已持有 2 把时武器项从池中过滤。
- **难度**：时间驱动，每 30 秒提升一档出怪频率、同屏上限与僵尸血量（初始间隔 2.2 秒、基础同屏 6，封顶 28；每档血量 +8%，封顶 2.5 倍）。出怪点必须离玩家 ≥320px、在屏幕外、且落点可通行（`World.findFreeSpot()` 口径）。
- **出怪池**：权重随玩家等级线性增长（`SURVIVAL_ZOMBIE_WEIGHTS`）——普通 / 狂奔 1 级起；飞扑者 2 级起、权重略低于同级狂奔；尖叫者 3 级起；胖子 4 级起；腐蚀者 4 级起、权重最低。BOSS 不走普通权重表：母体 8 级首次出现，之后每 3 分钟投放一只，同屏最多 1 只（`SURVIVAL_BOSS_POOL`）。求生与其他模式的僵尸数值互相独立：压制时长 / DPS、毒液 DPS 等差异只在 `SURVIVAL_ZOMBIE_OVERRIDES` 里覆盖，缺失字段回退基础定义。
- **HUD**：血量条、经验条与等级、存活计时、击杀数、强度档位；存在母体时画面顶部显示 BOSS 血条。升级为 DOM 三选一覆盖层，失败结算显示本局存活时间 / 等级 / 击杀与历史最佳。
- **记录**：`zombieGame.survival.v1` 只保存最佳存活时间与最高等级；「重开」与重新进入都从零开始。
- **快捷键**：`WASD` / 方向键移动，`Space` 暂停 / 继续，`R` 重开，升级时 `1–3` 选择卡片。

全部数值集中在 [config.ts](./src/data/survival/config.ts)；会话在 [session.ts](./src/survival/session.ts)，UI 在 [ui.ts](./src/survival/ui.ts)。

## 训练场

### 入口与隔离

主菜单点击「🧪 训练场」，或直接访问 `#/training`。

训练场是一个和正常对局完全独立的 `World`：

- 每次进入都会新建空世界、清零统计；返回主菜单时整个会话被丢弃，改动和单位都不会残留。
- 不修改全局设置（只读定义默认值 + 玩家覆盖值），因此不会影响之后开始的对局。
- 训练场里的人类固定为「进攻」模式，没有正式对局的准备阶段、放置与库存逻辑。
- 没有波次状态机、不会自动刷怪、没有胜负判定。
- 顶部「地图」下拉可切换地图：内置图与工坊图分组列出；换图会重建 `World`、流场与整层静态地图，并清空单位 / 选中状态 / 全部读数，避免跨图混算。工坊「用当前图试玩」进入的 `workshop-draft` 也会出现在「工坊地图」组。

### 生成与删除

1. 在「僵尸单位」或「人类单位」里点一个类型（按钮会高亮）。
2. 点击战场空地即可生成一个真实存活单位；可以连续点击生成多个。
3. 生成的单位照常走 AI、弹道、伤害与感染逻辑。

其他工具：

- 「🖱 选择/编辑」：点战场上的单位选中它。
- 「🗑 删除」：点单位直接删除；选中单位后编辑器里也有「删除该单位」。
- 「🧹 清场」：清空所有单位、弹道、特效、毒液与飘字。
- 「↺ 读数清零」：只清统计和时间，不清单位（方便用同一批单位对比另一组武器）。

生成限制：僵尸不能生成在墙体或实体障碍里（点在实心处会被忽略）；人类会被夹到房间可行走范围内。僵尸可以生成在房间外，便于测试其从走廊冲入的行为。

### 属性编辑

选中单位后，右侧编辑器直接写回该单位字段，立即生效：

- 僵尸：血量（同时更新上限并回满）、移动速度、撕咬间隔（越小越频繁地咬人 / 拆门窗）、攻击力（每次撕咬对人类的掉血量）。
- 人类：武器下拉（切换到任意一种武器，并重置弹药、冷却与喷火状态）、血量、移动速度、视野、伤害倍率（0.2–5）、射速倍率（0.2–5，倍率越大冷却越短）、无敌（完全免疫撕咬掉血与异变）。
- 感染转化中的人类如果勾上无敌，转化倒计时会立即清零，不会被转化。

僵尸攻击力只影响咬人掉血，不影响拆门窗（啃建筑伤害由门窗配置里的「啃建筑伤害」决定）。飞扑者 / 腐蚀者会自动出现在单位按钮与统计行，专属行为参数不可在此编辑（见上文的定义文件），但血量 / 移速 / 撕咬间隔 / 攻击力仍可逐单位调。

### 节奏控制

- 「⏸ 暂停 / ▶ 继续」：冻结逻辑，画面照常渲染。
- 「⏭ 单步」：自动暂停并只前进固定一帧（1/60 秒），便于逐帧观察弹道和命中。
- 「0.25x 慢放」：逻辑以四分之一速度推进。
- 「1x 正常」：恢复常速。

训练场快捷键（仅在该路由生效）：

| 按键 | 作用 |
|---|---|
| `空格` | 暂停 / 继续 |
| `.` 或 `N` | 单步一帧 |
| `1` | 恢复正常速度 |
| `0` | 0.25x 慢放 |

### 实时读数

面板每 120ms 刷新一次，包含：

- 顶部：累计运行时间（不含暂停）、存活人类数、存活僵尸数、总击杀。
- 人类挨咬：被咬次数、累计掉血、异变完成数（与武器 DPS 表分开统计）。
- 电击枪链式读数：放电次数、命中僵尸数、单发平均命中数、单体加成触发次数（独立口径，不混进武器 DPS 表）。
- 武器表（按武器聚合）：总伤、平均 DPS、最近 4 秒滚动 DPS、击杀数、平均击杀耗时。
- 僵尸类型表（按类型聚合）：存活数、承受伤害、被击杀数、平均击杀耗时。
- 伤害飘字：命中时在丧尸头顶显示实际生效伤害，同屏最多 160 条。

统计口径：

- 武器表与僵尸「承伤」只统计人类对僵尸造成的伤害；「人类被咬 / 掉血 / 异变」是僵尸对人类的反向读数，两者不混算。
- 总伤按「实际生效伤害」累计（不超过目标剩余血量）。
- 平均 DPS = 累计伤害 / 累计运行时间。
- 最近 4 秒 DPS 用 8 个 0.5 秒的滚动桶计算。
- 平均击杀耗时 = 单位从「训练场生成」到死亡的平均时间。仅统计训练场手动生成的僵尸。

### 视觉区分

训练场会额外绘制青色全场网格、虚线房间边框、四角标记与地面靶心；选中单位画 8 段弧高亮。正常对局不显示这些装饰。

## 工坊编辑器（阶段 2）

工坊是内容生产工具，**只对开发者模式开放**：先在主菜单「设置 → 开发者模式」输入密码开启，主菜单才会出现「🛠 地图工坊」入口；玩家模式完全不显示入口，直达 `#/workshop` 会被挡回主菜单并提示（仅为界面层拦截，不是安全边界，见下文「开发者模式」）。地图选择在训练场面板提供（阶段 3），工坊产出的草稿图可直接在训练场下拉里试玩。左上角「← 主菜单」退出。

- 左侧常驻**地图列表**：分「内置地图（只读）」与「我的地图」两组，每项只显示名称（内置图带「只读」标记，不显示 id）；列表下方是「＋ 新建地图」（空白 `74 × 45` 画布）与「⧉ 复制当前地图」（内置图也可复制，副本名称自动生成并参与全局唯一校验，之后可改）。点击列表项即切换地图，同时重置画布、撤销历史、选中项与工具状态；当前有未保存改动时先弹确认。原先的「载入内置图」下拉已并入该列表，不再保留第二套切换控件。
- 画布固定 `74 × 45` 格、`16px` 一格（`1184 × 720`），不做自定义尺寸；网格可见，悬停高亮当前格，滚轮以光标为中心缩放，右键 / 中键 / 空格 + 左键拖拽平移。
- 画笔：空地、墙、门、窗、人类区、僵尸区、擦除。门 / 窗按拖拽起点与终点决定宽度（必须落在 16px 的整数倍），拖动时实时显示拟定净宽（px / 格数）、默认血量与通行速度；默认值可在左栏「新门窗默认值」修改。人类区与僵尸区按拖拽画矩形，**可放多块**（多区按并集生效，人类区只决定出生点，僵尸区按面积加权出怪）。
- 擦除门窗会还原成墙；撤销 / 重做支持 `Ctrl/Cmd+Z` 与 `Shift+Ctrl/Cmd+Z`，历史栈上限 100 步；清空也可撤销。
- 左栏列出全部门窗，可直接改单扇 `maxHp` / `passSpeed` 或删除；区域列表同样列出每块人类区 / 僵尸区，点击可选中并定位，选中后拖动可调整位置，`Delete` / `Backspace` 删除（与门窗选中互斥）；右侧小地图与视口框实时跟随。
- 校验面板共用 `validateMapJson()`：至少 1 扇门（完全空白的画布豁免）、至少 1 块人类区与僵尸区且世界可达、区域落在空地且不与人类区冲突、每扇门窗两侧可通行；名称去首尾空格后 1–24 字且全局唯一（区分大小写）。带坐标的错误可点击跳到对应格。
- 草稿自动写入 localStorage（250ms 防抖），刷新或重进 `#/workshop` 自动恢复；可导入 / 导出 `public/maps` 可直接使用的 JSON（含 `schemaVersion`）。**用户只填名称，id 由系统生成**（`ws-<时间戳>-<4位随机十六进制>`，冲突自动换一个）；内置地图只读，需先「复制当前地图」为我的地图，副本同样会检查名称唯一。
- 校验通过后「用当前图试玩」：`compileTilesToMapDef()` 即时编译，草稿注册为运行时地图并跳到 `?map=workshop-draft#/training`，不写入 `public/maps`。
- **保存到项目（仅开发态）**：`npm run dev` 下工坊会出现「💾 保存到项目（dev）」按钮，把当前图写入 `public/maps/<id>.json` 并自动登记 `manifest.json`（`readOnly: false`），训练场地图下拉保存后即可选到，不需要整页刷新。服务端只接受本机（loopback）请求，非本机 403；远程开发需显式设 `VITE_WORKSHOP_ALLOW_REMOTE=1`。覆盖已有地图前会先备份到 `public/maps/.bak/`，每个 id 只保留最近 5 份（`.bak/` 与 `*.tmp` 已被 git 忽略）。内置只读图不能覆盖；id 重名会先弹确认，名称重名直接 409 并指出冲突图名。**这不是发布通道**：`vite build` 会把保存按钮与接口整段剥离，`npm run preview` 下按钮不存在、接口 404，正式发布仍需提交 JSON 与 manifest。
- **删除当前地图（仅开发态）**：在左侧地图列表选中 `readOnly:false` 的工坊图后可用「🗑 删除当前地图」，只对未被关卡 / 模式引用的图生效，点击后二次确认。服务端 `POST /__workshop/delete` 会先备份到 `.bak/`，再移除 manifest 条目并保持 2 空格 + 末尾换行；内置图 403、未知 id 404、被引用 409。删除成功后工坊与训练场下拉热刷新，名称释放；若删的正是当前训练图，会自动切回 `arena` 并重建 World / 静态层。生产构建同样整段剥离。

## 关卡编辑器（0.6.0）

关卡编辑器与玩家共用同一个入口：`#/levels`。开发者模式下列表项多出「编辑 / 复制 / 删除」，顶部多出「＋ 新建关卡」；玩家模式这些按钮**整组不渲染**（不是禁用变灰），只看到已解锁关卡。内置教学关是只读的，只能「复制」后编辑。直达路径 `#/levels/edit?id=<id>` 只在开发者模式生效；玩家模式访问会被挡回 `#/levels` 并弹出提示。

- 编辑器是一个整页弹层（不改路由），可改名称、绑定地图（下拉来自已注册地图）、每类武器的启用 / 血量 / 初始库存 / 上限 / 恢复间隔，以及波次列表（增删波、每波增删僵尸行、只数、间隔）。
- 新关 id 由系统生成（`lv-<时间戳>-<4位随机十六进制>`），用户只填名称；名称去首尾空格后 1–24 字、全局唯一且区分大小写，客户端预校验 + 服务端二次校验，重复直接拦截。
- 校验沿用 `validateLevelJson()`：绑定地图必须已注册、至少 1 波、每波至少 1 只、至少启用 1 种人类；不通过时表单底部列出错误并禁用保存。
- **保存 / 删除只在开发态**：`npm run dev` 下写入 `public/levels/<id>.json` 并自动登记 `public/levels/manifest.json`（`readOnly: false`）；只接受 loopback，覆盖前备份到 `public/levels/.bak/`（每个 id 最近 5 份），原子写入、失败回滚、进程内串行队列。保存 / 删除成功后热刷新选关列表，不整页刷新。生产构建整段剥离，`npm run preview` 下接口 404。
- 删除保护：只读关不可删；未来新模式可通过 `registerLevelReference()` 登记引用，被引用的关卡会返回 409 并说明原因。
- 「复制」会以当前关卡为模板生成新名称与系统 id，武器 / 波次配置原样保留，方便在只读教学关基础上改数值。

## 开发者模式

- 位置：主菜单「⚙ 设置」弹窗里的「开发者模式」区块。玩家默认关闭，只显示密码输入框与「开启」按钮；开启后显示状态说明与「退出开发者模式」按钮。
- 密码：优先读取 `.env.local` 的 `VITE_DEV_PASSWORD`（该文件已被 git 忽略，不提交）；变量缺失或为空时回退内置默认值 `zb9993`。按回车等同于点「开启」。
- 状态：开关写入 localStorage 的 `zombieGame.devMode.v1`，刷新页面后保持；点「退出开发者模式」立即清除。
- 效果：开发者模式下主菜单出现「🛠 地图工坊」入口，可进入 `#/workshop`；`#/levels` 全关解锁并出现「新建 / 编辑 / 复制 / 删除」。退出后工坊入口消失，当前若还停在工坊页会自动回到主菜单，已打开的关卡编辑器会关闭并在离开选关页时自动收起，之后直达 `#/workshop` 会被路由守卫挡回主菜单并显示 `.map-notice` 提示；选关页恢复玩家态（这些开发者按钮整组不渲染，只显示已解锁关卡与锁定条件）。
- **这不是安全边界**：纯浏览器游戏没有后端账号，玩家改 localStorage 或直接构造状态仍可绕过，这里只做界面层显隐。真正的隔离需要服务端发布或维护两套构建产物。

## 技术栈

| 方面 | 选型 |
|---|---|
| 语言 | TypeScript 5.7（`strict` / `noUnusedLocals` / `noUnusedParameters`） |
| 构建 | Vite 6 |
| 渲染 | PixiJS 8.6（WebGL/WebGPU），绘制到 Canvas |
| UI | 原生 DOM + CSS，HUD 与训练场面板均为覆盖层 |
| 音频 | Web Audio API（`AudioBuffer` 预加载 + 全局限频） |
| 路由 | 自写 hash 路由（`#/menu`、`#/levels`、`#/play`、`#/training`、`#/workshop`） |
| 存档 | localStorage + File System Access API + JSON 导入导出 |
| 测试 | `npm run regression`（Node + esbuild 加载真实模块跑 18 个场景）；行为仍以浏览器实跑为准 |
| 桌面版 | Electron + electron-builder；主进程在回环地址起只读静态服务加载 `dist`，不使用 `file://` |

逻辑采用固定步长 1/60 秒 + 累加器：渲染帧率波动不影响模拟；速度倍率通过「一帧多走几步」实现。空间查询使用空间哈希网格，寻路使用 BFS 流场，子弹与飘字使用对象池 / 数量上限控制内存与 GC 压力。

各模块职责边界：

- `data/` 是唯一的数值来源：实体数值写在各自的定义文件里，地图几何写在地图定义里，玩家改动只作为「覆盖值」保存在设置中，读取时合并。调平衡优先改定义文件。
- 新增僵尸 / 武器 / 人类 / 地图只需新增一个定义文件并在对应注册表登记一行，训练场按钮、统计列与 HUD 会自动跟随，不需要改玩法或 UI 代码。
- `core/world.ts` 只存状态与查询，几何从构造时传入的地图读取；行为在 `systems/`。
- `core/game.ts` 只决定「准备阶段、何时生成、何时结束」，放置与库存恢复也在这一层。
- 训练场通过 `World` 上的可选字段与 `onDamage` / `onKill` 钩子复用现有玩法，不复制平行逻辑；不设置这些字段时，正常对局行为与之前完全一致。

## 快速开始

环境要求：Node.js 18 及以上（Vite 6 的最低要求），npm。

```bash
npm install
npm run dev       # 开发服务器，默认 http://localhost:5173/
npm run build     # tsc --noEmit 类型检查 + vite build，产物输出到 dist/
npm run preview   # 本地预览 dist/ 构建产物
npm run regression # Node + esbuild 回归脚本（18 个场景，失败返回非零退出码）
npm run app:build # 先 build，再按当前平台打包桌面版（macOS 输出 dmg）
npm run app:build:win # 在 Windows 上先 build，再出 NSIS 安装包
```

**必须通过 HTTP 服务访问，不能双击 `index.html`。**

原因：`index.html` 通过 `<script type="module" src="/src/main.ts">` 加载源码，浏览器在 `file://` 协议下会拒绝模块加载与部分资源请求，路径也会解析错误；构建后的 `dist/` 同样需要 `npm run preview` 或任意静态文件服务器。直接双击打开只会得到空白页或控制台报错。

## 桌面版（Electron）

桌面版把同一份 `dist/` 构建产物装进 Electron 外壳，玩法与浏览器版一致（放置抵抗、尸潮求生、训练场）。**桌面版不支持地图工坊的保存 / 删除**：这些入口只存在于 `npm run dev`，生产构建里已剥离。要新增 / 修改地图，请在本机跑 `npm run dev` 进 `#/workshop` 编辑并「保存到项目」，再重新 `npm run app:build` 打包。

### 前置

- Node.js 18 及以上（与「[快速开始](#快速开始)」相同）、npm。
- 首次打包前先安装依赖：`npm install`（会把 `electron` 与 `electron-builder` 装进 devDependencies）。

### 打包

```bash
npm install
npm run app:build      # macOS：先 tsc + vite build，再出 .app 并封装 dmg
npm run app:build:win  # Windows：先 build，再出 NSIS 安装包
```

- 产物统一放在仓库根目录的 `release/`，文件名里的 `<version>` 取自 `package.json`，`<arch>` 跟随打包机器（如 `arm64` / `x64`）：
  - macOS：`release/ZombieSwarm-<version>-mac-<arch>.dmg`（分发用），以及 `release/mac-<arch>/ZombieSwarm.app`（可直接拖进「应用程序」）。在 Apple Silicon 上打包得到 `mac-arm64`，Intel Mac 上得到 `mac-x64`。
  - Windows：`release/ZombieSwarm-<version>-win-<arch>.exe`（NSIS 安装包，安装时可自选目录，非一键安装）。
- **`release/` 已写入 `.gitignore`，打包产物不提交**；`git status` 里看不到它。
- 打包流程：`npm run app:build` 先 `tsc + vite build`，再由 `electron-builder` 产出 `.app`，最后在 macOS 上用 `scripts/make-dmg.mjs` 调 `hdiutil` 把 `.app` 封成 dmg。DMG 不走 electron-builder 的 dmgbuild，避免受限环境写挂载卷隐藏文件被拦截。
- 主进程启动时在 `127.0.0.1` 的随机端口起一个只读静态服务指向 `dist`，再 `loadURL`，因此地图 / 关卡 JSON 的 `fetch` 正常；窗口 1280×720、最小 960×600、可缩放，保留系统菜单栏，关闭窗口即退出。
- 本地调试：先 `npm run build`，再执行 `npx electron .`。
- 在 macOS 上交叉编译 Windows 安装包（已验证可出包，但未在 Windows 实跑）：`npx electron-builder --win nsis --x64 --publish never`。不指定 `--x64` 时按当前机器架构产出（Apple Silicon 会得到 `win-arm64`）。

产物未签名、未公证，首次启动会被系统拦截：

### 存档位置

桌面版沿用浏览器版的 localStorage 存档（设置覆盖值、关卡进度、求生最佳记录），位置固定在应用 userData 目录：

- macOS：`~/Library/Application Support/ZombieSwarm/`

## 美术资源

### 像素精灵

单位由 `src/art/` 里的 32×32 俯视像素精灵渲染，不是运行时用代码画的圆形。每个精灵是一个 `SpriteDef`（定义在 `src/art/types.ts`）：

| 字段 | 作用 |
|---|---|
| `id` | 稳定标识，渲染层按 id 取图；人类为 `human-<weapon>`，僵尸为 `zombie-<kind>` |
| `palette` | 字模 → 颜色的调色板，例如 `{ g: "#63a04b" }` |
| `frames` | 帧名 → 32 行字符串，每行 32 个字符，`.` 表示透明 |
| `anchor` | 32×32 内钉在单位逻辑坐标上的中心点（人形为 `(16,17)`） |
| `muzzle` | 开火帧的枪口坐标，子弹与火舌从这里出膛；无武器时为 `undefined` |
| `gameDiameter` / `footprintRadius` | 建议绘制直径与碰撞半径，用于预览页还原 1:1 大小 |
| `facing` | 统一为 `"up"`（枪口指向 -y），运行时按朝向旋转 |

人类与六把武器的组合精灵 `human-mg` / `human-flame` / `human-shotgun` / `human-rocket` / `human-tesla` / `human-sniper` 由 `src/art/composites.ts` 在模块加载时用 `bakeOverlay` 烘焙，产物是普通 `SpriteDef`；渲染层只按 id 取一张贴图，不再实时叠两层。

### 新增一个单位外观

1. 在 `src/art/sprites.ts` 复制一个现有 `SpriteDef`，改 `id` / `name` / 调色板与帧矩阵，并登记进 `SPRITE_LIST`。
2. 如果是新武器的人类外观，在 `src/art/composites.ts` 的 `MUZZLE_BY_WEAPON` 与武器叠加逻辑里补上对应 id，烘焙会自动生成 `human-<weapon>`。
3. 在数据层新增对应实体：僵尸加 `src/data/zombies/` 并登记到注册表，武器加 `src/data/weapons/`。
4. 打开预览页核对 1×、游戏内尺寸与 8× 放大，并确认 anchor / muzzle 标记落在正确位置。

`src/art/` 不 import 游戏其它模块；与引擎之间的换算（id 查表、朝向旋转、缩放、枪口折算）集中在 `src/render/pixel.ts`。

### 新增实体交付清单

**1. 数据注册**

### 预览页 `sprites.html`

根目录的 `sprites.html` 是独立预览页：左 1× 原生、中按 `gameDiameter` 的游戏内尺寸、右 8× 放大；另有「接入自检」区块叠加 anchor（青色十字）、muzzle（粉色圈）与 `footprintRadius`（灰色虚线圈），可切换描边档位、像素网格与动画速度。

它和主游戏一样必须通过 HTTP 访问：

```bash
npm run dev
# 浏览器打开 http://localhost:5173/sprites.html
```

当前构建只以 `index.html` 为入口，`sprites.html` 仅用于开发期预览，不会进入 `dist/`。

### 视觉缩放

`src/render/pixel.ts` 的 `VISUAL_SCALE = 1.5` 是纯视觉倍数，只乘在精灵缩放上：

| 单位 | 碰撞半径 | 体型/逻辑直径 | 放大后绘制直径 |
|---|---|---|---|
| 人类 | 6 | 12 | 18 |
| 普通丧尸 | 5.5 | 11 | 16.5 |
| 狂奔丧尸 | 4.5 | 9 | 13.5 |
| 胖子丧尸 | 11 | 22 | 33 |

32px 精灵四周有透明留白，1.5 倍后人类可见宽度约 12.4px，接近 12px 的碰撞直径，所以看上去变大、判定没有变。僵尸同理：可见体宽约等于 2 × 碰撞半径（普通约 11.3、狂奔约 8.9、胖子约 22.5），通行判定用 2r，绘制盒宽用 2r × 1.5，1.5 只补透明留白，不再叠加到半径上。碰撞半径、速度、伤害、咬合距离、查询边距与寻路格子全部保持原值；枪口世界坐标同样按放大后的直径折算，子弹仍从枪口出膛。贴墙判定只按碰撞半径外扩，精灵不透明外廓与碰撞圆基本重合（人类约 12.4 / 12、普通约 11.3 / 11、胖子约 24.8 / 22），剩余差异 ≤ 1.4px，不需要为视觉再去放大碰撞半径；武器枪管等装饰不参与碰撞，贴墙时可能少量越入墙面。

## 音效系统

### 事件与文件

音效事件定义在 `src/audio/events.ts`，共 **22 个**：

| 分组 | 事件 |
|---|---|
| 武器 | 机枪射击、喷火、霰弹、火箭发射、火箭爆炸、电击枪放电、换弹 |
| 丧尸 | 追击咆哮、胖子低吼、啃咬、被命中、击杀、飞扑者索敌 / 起跳、腐蚀者索敌 / 吐毒、母体低吼 / 产卵 / 倒地、尖叫者尖叫 |
| 人类 | 受伤、转化倒戈 |
| 场景 | 波次开始、胜利、失败 |
| UI | 点击 |

`SFX` 的每个值同时是文件名主干，`SFX_MAP` 映射到 `audio/<事件名>.mp3`。文件放在 `public/audio/`，Vite 会原样拷贝到 `dist/audio/`，运行时以相对路径 `audio/...` 请求。

新增一个音效需要四步：

1. 在 `src/audio/events.ts` 的 `SFX` 里加事件；
2. 在 `SFX_MAP` 里登记 `audio/xxx.mp3`；
3. 在 `SFX_THROTTLE` 里设置全局限频（毫秒，`0` 表示不限频）；
4. 把同名 mp3 放进 `public/audio/`。

### 播放行为

`src/audio/manager.ts` 导出单例 `sound`：

- 启动时创建 `AudioContext`，用 `decodeAudioData` 预加载全部 22 个文件为 `AudioBuffer`。
- 播放时 `createBufferSource` 一次性输出，延迟低、并发稳定。
- 同一音效受 `SFX_THROTTLE` 全局限频（例如机枪 40ms、咆哮 3000ms），避免几十人同时开火导致音频爆炸。
- 文件缺失或解码失败时静默降级：该事件不发声，不抛错，只在控制台 `debug` 记录。
- 受浏览器自动播放策略限制，首次用户交互前不会出声；进入主菜单或选关页时会暂停音频，进入战斗或训练场再恢复。
- 支持总音量、音效音量、静音切换；音量滑块即时生效，其余参数在「重开」后生效。

### 授权台账

`public/audio/CREDITS.md` 逐文件记录来源、许可证与处理方式：

- 22 个 mp3 均为 **freesound.org 的 CC0 1.0 素材或其派生**（不含程序化合成文件），可复制、修改、商用，无需署名或授权费。0.8.0 起 `zombie-growl-fat.mp3` 与 `weapon-tesla.mp3` 已替换为独立实录（freesound 643766 / SnowFightStudios、488664 / Nodgez，提交 `6d2279d`）。

## 参数与存档

顶栏「⚙ 设置」打开参数控制台，共 21 个滑块，分 5 组：

| 分组 | 内容 |
|---|---|
| 波次 / 规模 | 总波数、首波尸数、波次增长、每秒最大生速、同屏僵尸上限 |
| 人类配置 | 初始人数、人类血量、移速、视野、转化倒计时 |
| 僵尸配置 | 属性随机幅度、普通/狂奔的血量与移速均值 |
| 门窗配置 | 门血量、窗血量、破窗后穿窗速度、啃建筑伤害与减速 |

修改滑块后点「重开」生效（音量即时生效）。「恢复默认」会清空所有覆盖值，回到各定义文件里的默认数值。

0.6.0 起正式对局的**波数、首波尸数、波次增长、开局人数**由关卡 JSON 接管，对应滑块不再影响对局；**生成速率、同屏上限、人类 / 僵尸 / 门窗数值**仍可在关卡 `settings` 或设置面板覆盖。训练场仍按设置面板的默认值生成单位。

滑块只记录「你改过什么」：设置里保存的是覆盖值，读取时按「覆盖值 ?? 实体/地图定义默认值」合并。`runtime.ts` 会按 id 读取任意僵尸的血量 / 移速覆盖值，但设置面板的滑块列表写在 `src/data/settings/sliders.ts`（静态），当前只登记了普通 / 狂奔；胖子暂时只能在训练场按单位调，或直接改 `fat.ts` 默认值。

### 关卡数据与进度

- 关卡运行时数据在 `public/levels/manifest.json` + `public/levels/<id>.json`，结构与地图 manifest 同构；关卡只存 `id`、`name`、`mapId`、`mode`、人类配置与波次配置，不复制地图数据。
- 启动时先 `await loadLevels()`；manifest 缺失、JSON 非法或校验失败会回退 `src/data/levels/level-1.ts` 的 TS 兜底，并在选关页顶部显示 `.map-notice` 提示。
- 选关页按 manifest 顺序展示；玩家模式逐关解锁（通关上一关即解锁下一关，首关默认解锁），开发者模式全部可玩。
- 进度保存在 localStorage 的 `zombieGame.progress.v1`；老存档里已有的「初次尸潮」通关记录会被沿用，不会把玩家打回未解锁。
- 开发者新增 / 编辑 / 删除关卡只写 `public/levels/<id>.json` 与 manifest，**不会自动创建新的「模式」或入口**：新关会直接出现在选关列表，玩家模式仍需按解锁顺序游玩；要接入其它模式需在代码里登记引用。

存档分三层兜底：

1. 每次修改自动写 localStorage；
2. 在支持的浏览器（Chrome / Edge + localhost 或 HTTPS）可选择本地目录，额外自动写 `settings.json`；
3. 支持导出 / 导入 JSON，便于跨设备搬运。

`0.3.0` 起设置存档格式变更（localStorage 键 `zombieGame.settings.v2`，`SAVE_VERSION = 2`）。旧版本存档不再兼容：读到旧格式时直接回落默认值，不抛异常、不阻塞启动；需要保留旧参数的话，请在升级前用「导出 JSON」备份。

主菜单「设置 → 清空存档」会删除 `zombieGame.progress.v1` 与所有 `zombieGame.challenge.*` 预留 key（预留 key，当前无实际数据），但**不会**删除 `zombieGame.settings.v2`、`settings.json` 或音量偏好，也不会删除开发者新建的关卡 JSON。清空后内存中的进度同步重置，下一次从首关开始。

## 已知限制

**玩法与数值**

- 人类血量是真实生命值，血量归零后不会立即死亡，而是进入约 2.8 秒的转化倒计时；转化中的仍算「存在」，转完才算消失。训练场可以调人类血量与僵尸攻击力来观察这个过程。
- 正式对局的人类补充完全依赖库存恢复，不再有「每波补 1 人」；库存恢复在准备阶段也会走表，暂停时不恢复。
- 胜负条件：放置模式胜利 = 打完全部配置波次，失败 = 已放置过人类后场上无人类；尸潮求生只有失败（玩家血量归零），没有胜利条件。
- 人类种类严格等于武器种类，关卡不能自定义新的「职业」或给同一武器配多档血量；血量、库存与恢复都读取关卡 JSON 的 `humans`。
- 开发者新建关卡保存后会立即出现在选关列表，但不会自动绑定到任何新游玩入口；玩家模式仍按 manifest 顺序逐关解锁。被引用的关卡通过 `getLevelReferences()` 保护，当前尚无模式登记引用，因此除只读外都可删除。
- 关卡编辑器不能改关卡 id，也不能编辑教学关里的 `settings` 兼容块；教学关只读，必须先「复制」。
- 关卡保存 / 删除只在 `npm run dev` 可用：`npm run preview` / `dist` 没有接口与按钮，默认只接受 loopback；生产构建会剥离编辑器代码、接口路径与保存 / 删除文案。
- 关卡 JSON 加载失败、manifest 非法或校验不通过时会回退 `src/data/levels/level-1.ts` 的 TS 兜底关卡，并在选关页显示提示；此时新增的工坊关卡不可见。
- 训练场「无敌」完全免疫撕咬掉血与异变；「人类血量」滑杆会真实改变该单位的初始/当前血量。
- 僵尸攻击力只有训练场按单位调整，尚未进入对局内全局滑块表；普通/狂奔/胖子的默认攻击力写在各自的 `src/data/zombies/*.ts`。
- 感染转化出来的新僵尸没有记录出生时间，因此**不计入平均击杀耗时**；它的击杀数仍会归入对应僵尸类型的击杀统计。
- 「清场」只清单位、弹道、特效与飘字，**不清读数**；要继续干净统计需点「读数清零」。
- 训练场没有波次、自动刷怪和胜负，人类固定为进攻模式，无法复现正式对局的准备阶段、放置与库存恢复。
- 「零人类时丧尸漫游」在正常对局里较难观察：波次中人类全部死亡会立即判负并停止推进。想验证漫游，请在训练场清场后生成僵尸，再单独生成 1 个人类观察恢复进攻。
- 胖子（`fat`）身体直径 22 > 窗洞净宽 16，按通用通行规则只能走门；破损的窗对它仍是实体墙，它也不会去啃自己钻不过去的窗。普通（11）与狂奔（9）仍可从破窗进入。
- 窗净宽 16px 下，破窗通行带对普通丧尸只剩约 5px；正式对局不再自动分岗，窗口火力线由玩家放置决定，觉得漏就优先在窗口前补人而不是放宽窗宽。
- 胖子的血量/移速暂时没有对局内设置滑块（滑块表静态登记了普通/狂奔），需要调它请用训练场单单位编辑或改 `src/data/zombies/fat.ts`。
- 尸潮求生只持久化「最佳存活时间」与「最高等级」两项，不保存当局升级组合、装备或进度；重开与重新进入完全清零。出怪忽略地图的人类区 / 僵尸区语义，仅按「离玩家 ≥320px、屏幕外、可通行」选点；「空旷地」以外的地图可能存在玩家被墙围住、XP 球落在不可达区域的情况。
- 尸潮求生的数值集中在 `src/data/survival/config.ts`，没有对局内滑块；升级奖励随机三选一，不提供刷新或跳过。双武器最多 2 把，副武器不显示在角色精灵上（只有 HUD 芯片）；「额外投射物」最多 4 层，电击枪每层只增加一道弧线且链式仍受 5 跳上限。0.8.2 的飞扑者 / 腐蚀者已接入求生出怪池（分别从玩家 2 级 / 4 级起出现），求生专属数值走 `SURVIVAL_ZOMBIE_OVERRIDES`（飞扑者压制 1.5 秒 / 4 DPS、腐蚀者毒液 4 DPS）。
- 地形只在地图瓦片层生效：草丛 / 水池需要在地图 JSON 或工坊 / 训练场里画出来，正式对局不能运行时新增；草丛燃烧与重生计时是全局统一的 1.5 / 10 / 1 秒，没有逐格差异。水池按设计要求不挡子弹与视线，只阻挡单位与寻路。
- 飞扑者蓄力与扑击只按「看得见」判断，不做区域路径规划：目标隔着一扇完整门窗时仍可能起跳，撞墙即算扑空并硬直 1 秒；扑击途中不会绕路。同一人类同时只能被 1 只压制，第二名飞扑者扑到已压制目标时按扑空处理。
- 压制伤害与世界毒液伤害不计入训练场的「人类被咬次数 / 掉血」统计（该口径只统计丧尸撕咬与人类武器输出），观察时以头顶血条与实际掉血为准。
- 飞扑者 / 腐蚀者的专属参数（蓄力时长、扑击倍率、压制时长与 DPS、毒液半径 / 持续 / DPS / 减速）没有对局内滑块，基础模式值在 `src/data/zombies/leaper.ts` 与 `corroder.ts`，求生模式差异值在 `src/data/survival/config.ts` 的 `SURVIVAL_ZOMBIE_OVERRIDES`；训练场只能逐单位调血量 / 移速 / 咬人间隔。
- 毒液按连续伤害结算（每帧 `dps × dt`），没有逐秒跳字；毒液不伤害丧尸、不影响僵尸寻路与索敌，也不能在正式对局运行时手动添加（只能由腐蚀者吐毒 / 死亡或调试代码产生）。

**工程与内容**

- 内置只有 1 个关卡（`level-1`「初次尸潮」，8 波共 1186 只），4 张只读地图（`arena` / `test-yard` / `test-multi` / `open-field`）。关卡以 `public/levels/*.json` + manifest 运行时加载（0.6.0），通过 `mapId` 引用地图；开发者可在 `#/levels` 新建 / 编辑 / 复制 / 删除 `readOnly:false` 的关卡，内置教学关只读。地图与关卡两套编辑器入口都只在开发者模式下显示；玩家模式直达 `#/workshop` 会被挡回主菜单，`#/levels` 只显示已解锁关卡。这些拦截都只是界面显隐，不是安全边界。
- 0.6.0 的关卡格式限制：`mode` 只支持 `placement`；人类种类只认武器 id；波次只支持「僵尸种类 + 只数」与波间间隔；关卡 `settings` 兼容块不在编辑器表单里，需手改 JSON。画布尺寸、门窗数量等仍受地图格式限制（固定 `74 × 45` 格 / `16px`）。
- 工坊草稿只存 localStorage，不能当作发布：试玩通过 `?map=workshop-draft` 注册运行时地图。0.5.1 起开发态可在工坊内「保存到项目」直接写 `public/maps/` 并登记 manifest，也可删除 `readOnly:false` 的工坊图（删除前同样备份、被关卡引用的图受保护；只允许 loopback，每个 id 留最近 5 份），但这些接口只存在于 `npm run dev`，生产构建会整段剥离，**不是发布通道**；正式发布仍需提交 JSON 与 `manifest.json`。工坊目前没有多人协同、图层或自定义画布尺寸。
- 地图 JSON 加载失败、manifest 非法或校验不通过时，会回退 `src/data/maps/arena.ts` 的 0.4.3 TS 兜底几何（画布 `1180 × 720`、窗宽 18），并在 console 输出 `[maps]` warning；正常路径下以 `public/maps/arena.json` 编译出的 `1184 × 720` / 窗宽 16 为准。请求地图 id 不存在时会回退默认图并在页面顶部显示 `.map-notice` 提示。
- 阶段 1B 折中：玩家设置的门 / 窗覆盖仍按种类统一生效，优先级高于逐扇 JSON 默认值；因此 `#/play` 下 `level-1` 的 `doorHp=450 / winHp=100 / winPassSpeed=0.45` 会覆盖 `test-multi` 的逐扇默认值，想看逐扇差异请用 `#/training` 或无关卡覆盖的场景。逐扇独立覆盖 UI 留到后续阶段。
- 音效：22 个事件已接线（0.8.2 新增 `zombie-growl-leaper` / `zombie-leap` / `zombie-growl-corroder` / `zombie-spit` / `zombie-growl-matriarch` / `zombie-spawn` / `zombie-matriarch-death` / `zombie-scream`），素材均为 freesound CC0 录音或其派生；缺文件时按现有逻辑静默降级。`weapon-reload` 与 `human-hurt` 仍没有调用点，放入文件也不会响。
- 美术：单位与武器使用像素精灵（`src/art/`，含 5 个 `human-<weapon>` 组合），运行时按朝向线性旋转，任意角会有轻微锯齿；母体使用 64×64 精灵网格，渲染层按 `SpriteDef.grid` 推导缩放与锚点，32×32 与更大网格共用同一套换算。特效与场景装饰仍由 Pixi 代码绘制。
- 电击枪是瞬时命中，链式最多 5 只且每跳都要求视线可见；未破的门窗会挡住后续跳跃，想观察满 5 跳请在训练场把僵尸排成一条并在同侧放置，或先把窗打破。链式半径/上限/衰减/单体加成都在 `src/data/weapons/tesla.ts` 的 `tesla` 字段，没有全局滑块。
- 母体产卵按环形采样找空地，周围被墙或其它地形完全堵死时会少产甚至本轮不产；死亡产卵同样受落点限制（开放地图可稳定产出 12 只）。母体与尖叫者不主动攻击人类，但仍会啃门窗；它们的撕咬伤害为 0，训练场统计里的「人类被咬」不会增长。
- 尖叫强化对同一只僵尸只保留最强倍率并刷新 6 秒计时，不叠加；BOSS 与尖叫者自身免疫。被强化僵尸的粉紫染色 / 粉环只活在渲染层，与压制标识（紫色）区分。BOSS 血条在多只母体时按「当前血量最高」选择展示对象，血量接近时可能发生切换。
- 求生 BOSS 为独立投放：玩家 8 级首次出现，之后每 3 分钟尝试一次，同屏最多 1 只；现有母体未死时计时停在 0，死亡后立即补下一只。求生普通出怪权重里的尖叫者为 3 级起、权重中等，具体数值在 `SURVIVAL_ZOMBIE_WEIGHTS`。
- `npm run regression` 提供 18 个场景的自动化回归（开口通行、碰撞、breach、求生经验 / 目标、JSON 校验、地形、双武器、额外投射物、狙击穿透与减速、飞扑压制与挣脱、毒液伤害 / 减速 / 不叠加、腐蚀者死亡留毒、母体产卵与死亡产卵、尖叫强化、求生池守卫），但它只覆盖逻辑层，不替代浏览器实跑；渲染、输入与 DOM 仍以 `#/play` / `#/survival` / `#/training` 手动验证为准。
- 面向桌面浏览器：训练场需要鼠标精确点选，未做移动端触控适配。
- 顶栏速度按钮支持 8x；速度只有按钮，没有键盘快捷键（数字键留给选择人类种类）。
- 训练场的单位、改动和统计不落盘，退出路由即重置；在训练场内切换地图同样会清空单位与全部读数（不跨图共用会话），退出再进入时回到进入训练场时指定的地图（`?map=` 或默认图）。
- 桌面版产物未签名、未公证，首次启动需要按「未签名如何打开」里的步骤放行；正式分发前必须签名 + 公证（Windows 需代码签名证书），否则 Gatekeeper / SmartScreen 会持续拦截。
- 桌面版不提供地图工坊保存 / 删除，也不加载 dev server；新建地图仍需在 `npm run dev` 的工坊里保存，再重新 `npm run app:build`。桌面版用户地图目录（`app.getPath("userData")/maps`）仍在待评估，没有实现。
- 桌面版主进程只监听 `127.0.0.1` 的随机端口并服务打包内的 `dist`，不对外提供 HTTP 服务；关闭窗口即退出，没有托盘驻留与自动更新。

## 版本与 CHANGELOG 约定

- 版本号遵循 [Semantic Versioning](https://semver.org/lang/zh-CN/)：`MAJOR.MINOR.PATCH`。当前处于 `0.x`，破坏性重构也可能出现在 `MINOR` 里，但会在 CHANGELOG 明确标注。
- `package.json` 的 `version` 是版本的唯一来源。发版时同步更新 `package.json`、`CHANGELOG.md`，并打 **annotated tag** `vX.Y.Z`：

```bash
git tag -a v0.8.1 -m "0.8.1: Electron 桌面版打包"
git push origin main
git push origin v0.8.1
```

- `CHANGELOG.md` 采用 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/) 风格，中文条目，新版本在上、旧版本在下；日期统一写 `YYYY-MM-DD`。
- 每个版本按需分组：`新增` / `变更` / `修复` / `移除` / `安全`；同一版本内按重要性排列。
- 尚未发布的内容写进 `Unreleased` 段。**只有实际完成并验证的内容才能从 `Unreleased` 移到版本段**，进行中的工作保持在 `Unreleased` 并注明「进行中」。
- 提交信息建议使用约定前缀：`feat:`、`fix:`、`docs:`、`perf:`、`refactor:`、`chore:`。本文件的维护提交使用 `docs:`。
